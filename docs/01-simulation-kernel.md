# 模拟内核

## 目标

模拟器内核只负责时钟语义。

它提供一次逻辑上升沿，驱动所有模块先求值，再统一提交下一拍状态。

## 一个周期

```text
cycle N 的 current
    -> 组合求值
    -> 各模块产生 next、事务请求、组合输出
    -> rising edge / commit
cycle N+1 的 current
```

## 8086 总线周期的 T1 到 T4

8086 的一次基本总线周期通常分为四个时序状态：

- `T1`：CPU 在地址线上输出地址，并通过 `ALE` 表示地址有效；
- `T2`：地址线转为数据线，CPU 表明读或写方向，并准备数据传输；
- `T3`：设备输出读数据，或 CPU 输出写数据；设备需要更多时间时，这里可以插入等待状态；
- `T4`：完成数据采样或写入，撤销控制信号，总线回到空闲状态。

当前内核没有把这四个状态建模为四个独立的 C 回调。它们由 `SimBusPhase` 表示，每次 `sim_kernel_tick()` 推进一个总线阶段。模块的 `drive` 阶段产生地址、读写方向和请求，BUS 根据当前阶段完成设备选择与数据响应，模块的 `sample` 阶段采样响应并生成下一状态，`sim_bus_finalize()` 在事务进入 `T4` 后提交设备副作用，最后由内核完成状态提交。普通内存访问通常经历 `T1 -> T2 -> T3 -> T4`，设备未准备好时会停留在 `WAIT`，直到可以进入 `T4`。

BUS模块 负责：

- 选择主设备；
- 选择响应目标；
- 推进 T1/T2/T3/WAIT/T4；
- 聚合 ready 和 error；
- 把事务记录进 trace。


## 现有实现

当前工程里，`sim_kernel_tick()` 是唯一的逻辑上升沿入口。`SimState` 保存整机公共状态，`SimTrace` 记录周期变化，`SimKernel` 负责把模块挂进去并在每拍调用它们。

`SimClock` 只管宿主时间到逻辑周期的换算。它不直接改状态。当前启动器使用固定批次推进，不追求宿主时间和 4.77 MHz 完全同步,因为存在启动器调度的问题。

## 内核职责

- 维护周期号；
- 驱动模块的 `drive / sample / trace`；
- 统一提交 `next` 状态；
- 处理复位、暂停、单步和停止请求；
- 让总线事务、IRQ 和设备状态在同一拍里对齐。
